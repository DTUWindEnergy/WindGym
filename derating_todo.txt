DERATING (PITCH CONTROL / DOWNREGULATION) — IMPLEMENTATION PLAN
=================================================================

Goal: Add per-turbine derating as a second action alongside yaw. Physically
accurate: derating changes the operating point on the power curve, which
reduces both power AND thrust (Ct), so the DWM particles downstream carry a
smaller deficit and less added TI.


PHYSICS
-------
Below-rated pitch control works by increasing pitch angle, which moves the
turbine to a lower operating point on the P(ws) and Ct(ws) curves. If the
current effective wind speed is ws_eff and we want to produce fraction f of
available power (f = 1 - derate, derate in [0,1]):

  1. Solve:  P(ws_op) = f * P(ws_eff)   for ws_op on the power curve
             (ws_op <= ws_eff, i.e. find the below-rated operating wind speed)
  2. Ct_derated = Ct(ws_op)
  3. P_derated  = P(ws_op)

This is physically correct because:
- ws_op < ws_eff → lower Ct → smaller DWM particles → less deficit and TI downstream
- The Ct reduction is not arbitrary; it follows the real turbine aerodynamics
- Works naturally for SWT23 which is often below rated in Lillgrund conditions

NOTE: Above-rated, pitch control reduces power but Ct stays roughly flat near
rated. The power-curve approach handles this correctly since Ct(ws_op) for
ws_op near rated is still well-defined from the tabular curve.

Solving P(ws_op) = f * P(ws_eff) requires a 1D root-find (scipy.brentq or
np.interp on the inverted power curve). The inversion is pre-computed once
over the ws range and stored as a lookup table for speed.


PYWAKE BUILT-IN SUPPORT
-----------------------
PyWake 2.6.11 has NO built-in derating/downregulation/curtailment support —
confirmed by searching the full source. The words "derate", "curtail",
"power_fraction", and "downregulat" do not appear anywhere.

However, PyWake's AdditionalModel plugin architecture (power_ct_functions.py)
is the right hook. Existing examples: SimpleYawModel (scales ws by cos(yaw),
scales Ct output) and DensityScale/DensityCompensation. The pattern maps
directly to derating: instead of scaling ws by cos(yaw), solve for ws_op such
that P(ws_op) = f * P(ws), then call f(ws_op, **kwargs).

Preferred approach: implement as an AdditionalModel subclass rather than a
full PowerCtFunction wrapper. Benefits:
  - No need to subclass PowerCtFunction or change the turbine object's type
  - optional_inputs propagation (sensor → powerCtFunction) works automatically
  - Composable with SimpleYawModel + DensityScale already in default_additional_models
  - Pass via additional_models=[..., DeratingModel()] at PowerCtTabular construction

The DeratingPowerCtFunction wrapper approach below remains valid as a fallback
if AdditionalModel turns out insufficient, but try AdditionalModel first.


STEP 1 — DeratingModel (AdditionalModel subclass)  [DONE]
----------------------------------------------------------
File: WindGym/WindGym/core/derating.py  (created)

Implement as an AdditionalModel that intercepts the ws→power_ct call:

  class DeratingModel(AdditionalModel):
      optional_inputs = ['derate']

      def __init__(self, ws_arr, power_arr):
          # ws_arr, power_arr from the turbine's tabular curve (used for inversion)
          AdditionalModel.__init__(self, input_keys=['ws', 'derate'],
                                   optional_inputs=['derate'],
                                   output_keys=['power', 'ct'])
          self._build_inverse(ws_arr, power_arr)

      def __call__(self, f, ws, derate=None, **kwargs):
          if derate is None or np.all(derate == 0):
              return f(ws, **kwargs)
          frac = 1.0 - np.clip(derate, 0.0, 1.0)   # power fraction [0, 1]
          ws_op = self._invert_power_curve(ws, frac) # find operating ws
          return f(ws_op, **kwargs)

      _build_inverse: pre-computed lookup (np.interp on inverted P(ws) table).
      Below cut-in or frac=0: ws_op → 0 (turbine off). frac=1: ws_op = ws.

Usage: at turbine construction time, pass additional_models=[SimpleYawModel(),
DensityScale(), DeratingModel(ws_arr, power_arr)] to PowerCtTabular.
The 'derate' optional_input then flows through automatically from sensors.

Fallback — DeratingPowerCtFunction wrapper (if AdditionalModel is insufficient):
  Subclass PowerCtFunction, add 'derate' to optional_inputs, forward ws_op to
  the wrapped base function. Replace wt.powerCtFunction at env init time.


STEP 2 — Dynamiks sensor hookup  [DONE]
-----------------------------------------
Because Dynamiks' PyWakeWindTurbines.get_kwargs() automatically passes any
sensor whose name matches an optional input of the powerCtFunction, we only
need to add a 'derate' sensor:

  fs.windTurbines.add_sensor('derate', expose=True)
  fs.windTurbines.sensors.derate = np.zeros(n_turb)   # initialise to no derating

After this, setting fs.windTurbines.sensors.derate = derate_values each step
automatically flows through ct() → rotor_avg_induction() → DWM particles.
No changes needed inside Dynamiks itself.

Where to add this: in wind_farm_env.py, in the block that initialises the
Dynamiks flow simulation (after fs is created, before the first step).


STEP 3 — PyWake adapter hookup  [DONE]
----------------------------------------
The PyWakeFlowSimulationAdapter does not use the Dynamiks sensor system. Its
_compute_steady_state() calls the PyWake model directly. We need to:

  a. Store derate values on the adapter: self._derate = np.zeros(n_turb)
  b. In _compute_steady_state(), compute effective ws_op per turbine using the
     same power-curve inversion as Step 1, then override the Ct passed into
     the model call (or pass a modified turbine object).
  c. Simplest implementation: after steady-state, post-correct _power_eff and
     compute derated Ct per turbine, then re-run with a custom per-turbine Ct.

     PyWake supports per-turbine Ct via the 'ct' kwarg in the model call for
     some models, or via a custom WindTurbines subclass. Use the same
     DeratingPowerCtFunction wrapper — attach it to the turbine before
     constructing the model, same as Dynamiks.

      derate_raw = action[self.n_turb:]          # [-1, 1]
      derate = (derate_raw + 1) / 2              # map to [0, 1]
      derate = np.clip(derate, derate_min, derate_max)

          fs._derate = derate

STEP 6 — Reward
-----------------
No special reward term needed — derating reduces farm power directly, so the
existing power reward already penalises unnecessary derating. The agent must
learn that upstream derating is only worth it if the downstream gain exceeds
the upstream loss.

Optionally add a derate change penalty (like action_penalty for yaw) to
discourage rapid derating oscillations:
  config key: derate_penalty, derate_penalty_type: 'change' | 'total'
